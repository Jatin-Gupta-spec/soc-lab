# INV-002: Sysmon-to-Wazuh integration gap

## What happened
After adding a <localfile> entry for Microsoft-Windows-Sysmon/Operational to the
Wazuh agent group config, the agent log showed:
  ERROR: Could not EvtSubscribe() for (Microsoft-Windows-Sysmon/Operational)
  which returned (15000)
Windows documents error 15000 as "invalid channel path".

## Investigation
- Confirmed via Get-ChildItem and Get-Content that the config had synced to the
  agent (checksum changed, file present on win-client).
- Confirmed via Event Viewer that the channel itself was valid (236+ Sysmon
  events already visible on the endpoint).
- Measured the exact channel string length with PowerShell:
  ([xml](Get-Content ...)).agent_config.localfile.location.Length
  Expected: 36 characters. Actual: 37.

## Root cause
An extra hidden character (likely a stray space or line break introduced while
typing into the dashboard's web-based XML editor) made the channel path
technically invalid, even though it displayed correctly on screen.

## Fix
Cleared the agent.conf editor completely and retyped the block as one
continuous entry. Re-measured: 36 characters, correct.

## Retest
Restarted the WazuhSvc service. Generated a test event (opened/closed Notepad).
Searched Discover: agent.name:win-client AND data.win.system.providerName:"Microsoft-Windows-Sysmon"
Result: 27 hits. Confirmed working end to end.

## Gap code
G2 (telemetry generated, not correctly collected) — caused by a config
transcription error, not a missing setting.

## Lesson
A config that "looks right" on screen and even syncs successfully can still
silently fail. Measuring the exact value (character count) found what visual
inspection couldn't.
