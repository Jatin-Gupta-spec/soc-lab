# INV-003: PowerShell base64-encoded command (SC-002)

## Alert
Rule 92057, "Powershell.exe spawned a powershell process which executed a
base64 encoded command", level 12, agent win-client (001), mapped to
T1059.001 (Execution: PowerShell).

## Evidence
Sysmon Event ID 1 (Process Create):
- Image: C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe
- CommandLine: "...powershell.exe" -EncodedCommand VwByAGkA...
- User: WIN-O3AMM6R85SI\Administrator
- UtcTime: 2026-09-23 07:25:27.355

## Timeline (UTC)
- 07:25:27 PowerShell launched with -EncodedCommand
- 07:25:28 Alert 92057 raised (about 1 second later)

## Analysis
I ran a harmless base64-encoded PowerShell command from an elevated shell on
win-client, decoding to a single Write-Host line. Wazuh's default Sysmon
ruleset matched this pattern without any custom rule being written, and
correctly mapped it to T1059.001, the exact technique the scenario card
predicted.

## Verdict
True positive. Cause: my own authorised test. Confidence: high, I made the
exact command and know the exact time.

## What would change my mind
The same alert pattern appearing from a user account I didn't use, or a
command I didn't run.

## Detection gap
None. This confirms Wazuh's out-of-the-box Sysmon rules already cover this
technique; a custom detection wasn't needed here. (First earlier attempt
found no result because I searched too soon and with too narrow a field
match, not because of a real gap — a lesson on giving the pipeline time and
retrying with a fresh, precisely-timed test.)
