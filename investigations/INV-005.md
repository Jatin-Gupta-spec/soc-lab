# INV-005: Windows Application log cleared (SC-004)

## Alert
Rule 63104, "A Windows log file was cleared", level 5, agent win-client (001),
mapped to T1070 (Indicator Removal, Defense Evasion). Note: Wazuh mapped this
to the parent technique T1070, not the T1070.001 sub-technique predicted in
the scenario card; recorded as observed, not corrected to match the prediction.

## Evidence
Event ID 104 (Microsoft-Windows-Eventlog provider), channel: System:
"The Application log file was cleared."
data.win.logFileCleared.channel: Application
data.win.logFileCleared.subjectUserName: Administrator

## Timeline (UTC)
- 2026-09-25 01:48:57 wevtutil cl Application run; Event 104 logged and
  alerted in the same second.

## Analysis
Ran wevtutil cl Application from an elevated PowerShell session on
win-client. Windows itself logs the clearing action to a different log (the
System log), so even a fully successful "wipe" of the Application log
leaves a direct record elsewhere. Wazuh's default ruleset detected this
immediately with no custom rule.

## Verdict
True positive. Cause: my own authorised test. Confidence: high.

## What would change my mind
The subjectUserName field showing an account I didn't use, or the event
appearing without a matching PowerShell/wevtutil command in the timeline.

## Detection gap
None. Confirms log-clearing is well covered out of the box. Worth noting:
this only catches log-clearing done through the standard Windows API
(which wevtutil uses); a more sophisticated attacker directly manipulating
the log file on disk while the service is stopped could potentially evade
this specific event. Not tested here.
